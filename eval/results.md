# Evaluation results

Generated by `python -m eval.report` from `eval/results/*.json`. Corpus: 5,000 CC-News articles. Hardware: laptop CPU for embedding and reranking, qwen3 8B via Ollama.

## Summary
- **Chunking:** 25.6% of the original 400-word chunks were longer than the embedding model's 512-token limit and silently cut off; dynamic and semantic chunks: 0%.
- **Retrieval, hard questions (no names to match on):** the original setup (fixed chunks, dense only) finds the right article first 64.7% of the time (MRR 0.724). Semantic chunks + hybrid BM25/dense + rerank: 79.3% (MRR 0.84), and 90.0% in the top 5. BM25 wins on the name-heavy standard questions, dense catches up on vague ones, and hybrid + rerank beats either retriever alone at R@1 on every index and question set. Plain RRF weights the two lists equally and can trail the stronger one; the reranker recovers that.
- **Retrieval, standard questions:** R@1 82.0% → 91.2%, R@5 94.0% → 98.8% (dynamic chunks + hybrid + rerank).
- **What the LLM sees:** the source article is in the 5 passages 100.0% of the time (was 92.5%), with 22% fewer tokens per LLM call.
- **Semantic cache correctness:** embedding similarity alone would serve a *wrong* cached answer for 76.0% of near-miss questions. With the key-term guard and duplicate-question verifier: 0.0% wrong hits, while 92.7% of paraphrases still hit.
- **Latency:** p50 13.5 s on a miss (the LLM is 93% of it) vs 19 ms for an exact cache hit and 60 ms for a semantic hit; each hit skips an LLM call of ~1640 tokens.
- **Scale:** at 1,000,000 vectors, HNSW search takes 0.587 ms vs 45.27 ms exact (77.1x faster) at 96.6% recall.
- **Caveats:** questions are LLM-generated (one per article) over a 5,000-article corpus, so the standard set is near the ceiling; the hard set is the more informative one. Fusion weights were compared on the same questions they're reported on.

## Semantic cache

96 eval questions, each with an LLM-written paraphrase (should hit) and a near-miss with one key detail changed, e.g. "...eclipse in the Tri-Cities?" vs "...eclipse in Seattle?" (must not hit: it would return the wrong answer).

Embedding similarity alone can't separate them: median question-to-question cosine is 0.951 for paraphrases but already 0.902 for near-misses (unrelated questions: 0.381). So a vector match is only a candidate; it must also pass a key-term guard (no new names or numbers) and a duplicate-question cross-encoder (`cross-encoder/quora-distilroberta-base`, score ≥ 0.5, scored both ways; median 0.979 for paraphrases vs 0.001 for near-misses).

Paraphrase hit rate / near-miss false-hit rate, by minimum cosine similarity:

| Checks | ≥ 0.8 | ≥ 0.85 | ≥ 0.9 | ≥ 0.95 |
|---|---|---|---|---|
| vector only | 99.0% / 92.7% | 97.9% / 76.0% | 89.6% / 52.1% | 50.0% / 18.8% |
| vector + key-term guard | 95.8% / 9.4% | 94.8% / 9.4% | 86.5% / 8.3% | 49.0% / 3.1% |
| vector + verifier | 96.9% / 1.0% | 95.8% / 1.0% | 87.5% / 1.0% | 50.0% / 1.0% |
| vector + guard + verifier | 93.8% / 0.0% | 92.7% / 0.0% | 84.4% / 0.0% | 49.0% / 0.0% |

## Answer quality (40 questions)

baseline = fixed 400-word chunks + dense top 5 (the original main.py). full = dynamic chunks + hybrid RRF + cross-encoder rerank top 5. Context hit = the source article is among the 5 passages given to the LLM. Tokens = prompt + answer tokens per LLM call. The 1-5 scores come from an LLM judge (the same local qwen3) that also sees the passage the question was written from.

| Pipeline | Context hit | LLM tokens | Faithfulness | Relevance | Correctness |
|---|---|---|---|---|---|
| baseline | 92.5% | 2121 | 4.85 | 4.9 | 4.85 |
| full | 100.0% | 1649 | 4.92 | 4.97 | 4.83 |

The full pipeline always puts the right article in front of the LLM (92.5% → 100.0%) and uses 22% fewer tokens per call, because its chunks are shorter and on-topic. The judge scores are near the ceiling for both and noisy (in one case it gave identical answers a 5 and a 1), so they don't separate the pipelines on these questions.
